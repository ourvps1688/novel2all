## 验证方法论（本轮沉淀，后续必须沿用）

**1. server tsc 必须用「行号不敏感」口径。** 删代码会让错误行号整体下移，产生大批假新增。本轮实例：`NovelWorkflowStoreService.ts` 偏移恒为 89、`autoDirectorAutoApprovalAudit.ts` 偏移 14。
- 行号敏感口径：before 867 / after 865，NEW 12（**全是假阳性**）
- 行号不敏感口径（`sed -E 's/\([0-9]+,[0-9]+\)//'` 后按 `文件|错误码|计数` 聚合）：before 217 / after 215，**NEW 0 / FIXED 2**
- 基线取法：`git checkout <baseline-commit>` 跑一次再切回分支（需先提交未暂存改动）

**2. client 测试必须抓「失败用例名集合」做差集**，不能比总数（总数相同不代表无新增）。本轮 before 173/159/14 → after 171/157/14，**NEW 0 / FIXED 0**。

**3. 服务端测试在本环境永远跑不起来**：`server/dist` 需要 `prisma generate` 产出 `.prisma/client`，而 prisma CLI 因 esbuild postinstall 被沙箱拦截而不可用。实测报错 `Cannot find module '.prisma/client/default'`。**只能靠 tsc 类型比对 + require 路径可达性校验 + node --check 语法校验替代**。要真跑需用户在本地执行。

**4. 环境工具路径**（node_modules 不完整，`.bin` 不存在）：
- tsc：`node ../node_modules/typescript/bin/tsc -p tsconfig.json --noEmit`
- vite：`node ../node_modules/.pnpm/vite@7.3.1_@types+node@25.3.3_jiti@2.6.1_yaml@2.8.2/node_modules/vite/bin/vite.js build`
