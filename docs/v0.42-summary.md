# novel2all v0.42 — Cache 工程化加固收官报告

> **版本范围**：V0.40 → V0.43（**4 个核心 commit**：V0.40 1 + V0.42 1 + V0.43 1 + V0.41 docs 1）
> **完成时间**：2026-09-13
> **状态**：✅ 全部 ALL_GREEN，远端 main = `d1bd864`
> **核心主题**：**从"SQLite 单连接"到"工程化 Cache 体系"**——连接池（V0.42）→ 自动 backup（V0.42）→ 多 backend 平滑迁移（V0.43）→ LLMProvider 显式 close（V0.42）

---

## 1. 目标

V0.40 SQLite backend 留下 **5 个工程化限制**：

| # | 限制 | 影响 | 解决版本 |
|---|------|------|----------|
| 1 | SQLiteBackend 多线程需 `threading.Lock`（单连接） | 高并发性能差 | V0.42 连接池 |
| 2 | LLMProvider 启动时不显式 close SQLite 连接 | 进程退出时连接泄漏 | V0.42 `close()` |
| 3 | cache.db 损坏时不会自动恢复 | 需要手动删 db 重启 | V0.42 自动 backup |
| 4 | JSONFile → SQLite 升级时丢失所有数据 | 用户不敢升级 | V0.43 平滑迁移 |
| 5 | CacheBackend Protocol 不完整（无 keys()/close()） | migration 工具无法统一接口 | V0.43 Protocol 扩展 |

**V0.42-V0.43 主旋律**：把 V0.40 的"原型 SQLite backend"升级为"企业级 Cache 体系"——并发 + 容错 + 迁移 + 资源管理。

## 2. 关键决策（基于失败教训 + 工程最佳实践）

| # | 版本 | 决策 | 数据来源 |
|---|------|------|---------|
| 1 | V0.42 | **thread-local 连接池**（替代单连接 + 全局锁） | FastAPI 线程池默认 40 线程，单连接成为瓶颈；每线程独立 conn = 无锁并行 |
| 2 | V0.42 | **integrity_check 启动恢复**（损坏 → backup → 重建） | 磁盘故障 / 进程崩溃可能导致 db 损坏；自动 backup 避免数据丢失 |
| 3 | V0.42 | **magic 头检查**（替代 integrity_check 作为第一道关卡） | Windows 上 integrity_check 抛"file is not a database"会锁住文件，无法 rename |
| 4 | V0.42 | **try/finally 关闭 test_conn** | integrity_check 失败抛异常时连接未关闭，rename 失败 |
| 5 | V0.42 | **清理 -wal/-shm/-journal 残留** | Windows rename 前需清残留辅助文件，否则重命名失败 |
| 6 | V0.42 | `LLMProvider.close()` + `__enter__/__exit__` | FastAPI lifespan / context manager 标准化资源管理 |
| 7 | V0.43 | **CacheBackend Protocol 扩展 `keys()/close()`** | 迁移工具需要统一接口读 entries；close() 释放资源 |
| 8 | V0.43 | **memory → 不支持迁移**（无 path 概念） | 简化 API；如需持久化先转 json/sqlite |
| 9 | V0.43 | **CLI auto-detect backend**（按扩展名 .json / .db） | 减少参数；用户友好 |
| 10 | V0.43 | **错误累积到 result.errors**（不中断） | 单条失败不应中断整批迁移 |

## 3. 完整 commit 链路（3 个核心 commit）

> **时间线**：2026-09-13，V0.40 → V0.43 = 约 1.5 小时

### 3.1 V0.40 SQLite backend（baseline） — `819d967`

**作用**：V0.40 是 V0.42-V0.43 改造的基础。详细见 `docs/v0.40-summary.md`。

**关键能力**：
- SQLite 内置锁（POSIX/Windows 通用，跨 OS 安全）
- WAL 模式（reader 不阻塞 writer）
- `INSERT OR REPLACE` 原子 upsert
- 零新依赖（sqlite3 是 Python 标准库）

**V0.40 限制**（V0.42-V0.43 要解决）：
- 单连接 + `threading.Lock` → 高并发性能差
- 无 `close()` → 进程退出连接泄漏
- 损坏 DB 不自动恢复

### 3.2 V0.42 连接池 + 自动 backup — `149482f`

**问题 1**：V0.40 单连接 + `threading.Lock` 串行化所有 DB 操作，高并发场景成为瓶颈。

**问题 2**：损坏的 cache.db 需要手动删 + 重启；V0.40 没有自动恢复机制。

**修复**（`core/cache.py` SQLiteBackend 重构 + `core/provider.py` 加 close）：

**2.1 Thread-local 连接池**：
```python
self._local = threading.local()  # 每线程独立存储
self._conns: list[sqlite3.Connection] = []  # 所有 conn 引用
self._conns_lock = threading.Lock()  # 仅保护 _conns 列表

def _get_conn(self) -> sqlite3.Connection:
    if not hasattr(self._local, "conn") or self._local.conn is None:
        conn = sqlite3.connect(...)  # 线程首次创建
        conn.execute("PRAGMA journal_mode=WAL")
        self._local.conn = conn
        with self._conns_lock:
            self._conns.append(conn)  # 加入池
    return self._local.conn
```

**2.2 自动 backup 流程**：
```python
def _check_and_recover(self) -> None:
    if not self._path.exists():
        return
    # Step 1: 快速 magic 检查（避免 integrity_check 锁住文件）
    with open(self._path, "rb") as f:
        header = f.read(16)
    if not header.startswith(b"SQLite format 3"):
        self._rename_corrupt()  # backup + 重建
        return
    
    # Step 2: integrity_check 深度检查
    test_conn = None
    try:
        test_conn = sqlite3.connect(str(self._path), timeout=5.0)
        result = test_conn.execute("PRAGMA integrity_check").fetchone()
        if result and result[0] == "ok":
            return
    finally:
        if test_conn is not None:
            test_conn.close()  # ← V0.42 关键：try/finally 关闭
    
    self._rename_corrupt()

def _rename_corrupt(self) -> None:
    # 清理 -wal / -shm / -journal 残留（Windows 必需）
    for suffix in ("-wal", "-shm", "-journal"):
        extra = self._path.with_suffix(self._path.suffix + suffix)
        if extra.exists():
            extra.unlink()
    backup_path = self._path.with_suffix(f".corrupt.{timestamp}.db")
    self._path.rename(backup_path)
```

**2.3 LLMProvider 显式 close + context manager**：
```python
def close(self) -> None:
    if hasattr(self._cache, "close"):
        self._cache.close()  # SQLite 关闭连接池

def __enter__(self) -> Self:
    return self

def __exit__(self, *exc_info: object) -> None:

```

**2.4 FastAPI lifespan shutdown**：
```python

@dataclass
class MigrationResult:
    src_backend: str
    dst_backend: str
    total_entries: int = 0
    migrated: int = 0
    skipped_expired: int = 0
    errors: list[str] = field(default_factory=list)
    elapsed_seconds: float = 0.0

def migrate_cache(src_backend, dst_backend, src_path, dst_path, ...) -> MigrationResult:
    src = _open_backend(src_backend, src_path, max_size=8192)
    dst = _open_backend(dst_backend, dst_path, max_size, ttl_seconds)
    try:
        for key in src.keys():  # V0.43 新方法
            value = src.get(key)
            if value is None:
                continue  # TTL 过期
            dst.set(key, value)  # dst 用统一 encode_key
    finally:
        src.close()
        dst.close()
```

## 6. 关键技术细节

### 6.1 Thread-local 连接池（V0.42）

```python
class SQLiteBackend:
    def __init__(self, path, max_size, ttl_seconds):
        self._local = threading.local()  # 每线程独立存储
        self._conns: list[Connection] = []
        self._conns_lock = threading.Lock()  # 仅保护 _conns 列表

    def _get_conn(self) -> Connection:
        # 检查 thread-local
        if not hasattr(self._local, "conn") or self._local.conn is None:
            conn = sqlite3.connect(
                str(self._path),
                isolation_level=None,
                timeout=5.0,
                check_same_thread=False,  # 但我们手动管理
            )
            conn.execute("PRAGMA journal_mode=WAL")
            conn.execute("PRAGMA synchronous=NORMAL")
            self._local.conn = conn
            with self._conns_lock:
                self._conns.append(conn)  # 加入池
        return self._local.conn
```

**为什么不用每线程一个连接 + connection pool**：
- FastAPI 线程池线程数动态变化（默认 40）
- 开 40 个连接太重（文件句柄 + 内存）
- 用单连接 + lock 简单但串行化
- 用 thread-local conn 平衡：线程数动态创建/复用，零竞争

### 6.2 Integrity_check 启动恢复（V0.42）

```python
def _check_and_recover(self) -> None:
    if not self._path.exists():
        return
    
    # Step 1: 快速 magic 检查（"SQLite format 3"）
    try:
        with open(self._path, "rb") as f:
            header = f.read(16)
        if not header.startswith(b"SQLite format 3"):
            self._rename_corrupt()
            return
    except OSError as e:
        self._rename_corrupt()
        return
    
    # Step 2: integrity_check（finally 关闭 test_conn）
    test_conn = None
    try:
        test_conn = sqlite3.connect(str(self._path), timeout=5.0)
        result = test_conn.execute("PRAGMA integrity_check").fetchone()
        if result and result[0] == "ok":
            return
    finally:
        if test_conn is not None:
            test_conn.close()
    
    self._rename_corrupt()
```

**为什么先用 magic 检查**：
- integrity_check 在文件无效时抛 "file is not a database" 异常
- 异常时连接不关闭 → 文件锁住 → rename 失败
- magic 头检查是纯文件 IO，不打开 SQLite 连接，无锁问题

**为什么 try/finally 关闭 test_conn**：
- 即使 integrity_check 失败，连接也要关闭
- 否则 Windows 上文件锁住，rename 失败

### 6.3 Windows -wal/-shm 清理（V0.42）

```python
def _rename_corrupt(self) -> None:
    timestamp = int(time.time())
    backup_path = self._path.with_suffix(f".corrupt.{timestamp}.db")
    
    # Windows 上需要先尝试删除可能残留的辅助文件
    for suffix in ("-wal", "-shm", "-journal"):
        extra = self._path.with_suffix(self._path.suffix + suffix)
        if extra.exists():
            extra.unlink()
    
    self._path.rename(backup_path)
```

**为什么**：WAL 模式下会生成 `.db-wal` / `.db-shm` 辅助文件。Windows rename 时如果这些文件存在，会失败。

### 6.6 migrate_cache 关键设计（V0.43）

```python
def migrate_cache(src_backend, dst_backend, src_path, dst_path, ...):
    src = _open_backend(src_backend, src_path, max_size=8192)  # 8192: 足够大
    dst = _open_backend(dst_backend, dst_path, max_size, ttl_seconds)
    try:
        for key in src.keys():  # V0.43 新方法
            value = src.get(key)
            if value is None:
                continue  # TTL 过期（src 自动跳过）
            dst.set(key, value)  # dst 端用统一 encode_key
    finally:
        src.close()  # V0.42 close()
        dst.close()
```

**为什么 src max_size=8192**：避免迁移时被 LRU 淘汰
**为什么 dst.set() 用统一 encode_key**：tuple key 自动编码为字符串，所有 backend 通用
**为什么 finally close()**：确保源/目标都关闭，V0.42 SQLite 池不会泄漏

### 2. 关键设计原则

| 原则 | 实施 |
|------|------|
| **后端抽象** | `CacheBackend` Protocol（V0.33 + 7 个方法） |
| **资源管理** | `close()` 方法（V0.42 新增）+ `LLMProvider.close()` + FastAPI lifespan |

| **容错** | V0.42 integrity_check + magic 头检查 + 自动 backup |
| **迁移** | V0.43 `migrate_cache()` + Protocol `keys()` + auto-detect backend |

### 3. 永远不要做的事

- ❌ **不要回退到 V0.40 单连接 + `threading.Lock`**（V0.42 已有 thread-local 池）
- ❌ **不要删除 `_check_and_recover()` 自动 backup**（损坏 DB 会导致启动失败）
- ❌ **不要回退到 V0.40 `PRAGMA integrity_check` 不带 finally 关闭**（Windows 锁文件）
- ❌ **不要在迁移时省略 TTL 过期检查**（带毒数据污染目标 cache）
- ❌ **不要写 `for key in backend.keys()` 不加 noqa**（ruff SIM118 误判，keys() 是 list 不是 dict）
- ❌ **不要忘了 `LLMProvider.close()` 或 FastAPI lifespan 调 close**（SQLite 连接池泄漏）

### 4. 添加新 backend 步骤（V0.43 完整版）

1. 实现 `CacheBackend` Protocol 的 **7 个方法**（V0.33 + V0.42 + V0.43）：
   - `get/set/size/clear/stats`（V0.33）
   - `close()`（V0.42）
   - `keys()` 返回 `list[str]`（V0.43）
2. `LLMConfig.cache_backend` Literal 加新值
3. `LLMProvider.__init__` 加 elif 分支
4. `stats()` 返回 dict 含 `backend/lock_backend/persist_path` 字段
5. 加单测（基础 + TTL + LRU + 跨实例持久化 + 线程安全 + close + keys）
