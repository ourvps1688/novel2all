## 3. 完整 commit 链路（9 个核心 commit 详细变更）

### V0.51 — Cache 智能推荐端点（commit `20c9caf`）

**问题**：V0.50 收官后 cache 配置依然靠"试错"。新用户不知道该用 memory/sqlite/redis 中的哪个、max_size 设多少、TTL 多少。

**实现**：
- `src/novel2all/core/cache_recommend.py`（386 行）：`recommend_cache_config()` + `CacheRecommendation` dataclass
- `src/novel2all/web/app.py`：2 个新端点
- `src/novel2all/web/templates/cache_recommend.html`：HTMX partial
- `src/novel2all/web/templates/index.html`：集成到 cache-panel 下方
- `tests/unit/test_cache_recommend_v0510.py`：**28 个新测试**

**核心算法**（4 维度加权）：

| 维度 | 权重 | 健康规则 |
|------|-----:|---------|
| backend_optimal | 30% | json → sqlite（45-185x 性能）|
| size_healthy | 25% | 利用率 50-80% 满 |
| ttl_healthy | 20% | ttl=0 + 高流量 → 86400 / 低命中 → 2x / 高命中 → 0.5x |
| hit_rate_healthy | 25% | > 80% = 100 / > 50% = 60 / < 30% = 0 |

**规则触发**（基于 V0.47 benchmark）：

| 触发 | 当前 → 推荐 | 预期影响 |
|------|------------|---------:|
| backend = json | → sqlite | 45-185x 性能 |
| backend = memory + queries > 1000 | → sqlite | 节省 30-50% LLM 成本 |
| backend = sqlite + size ≥ 95% | → redis | 多实例共享 |
| max_size 利用 ≥ 95% | 2x current | 命中率 +5-15% |
| max_size 利用 ≤ 30% + size ≥ 100 | 0.5x current | 节省内存 |
| ttl = 0 + 高流量 | → 86400（24h） | 防 stale |
| ttl > 0 + hit_rate < 30% | 2x ttl | 命中率 +5-10% |
| ttl > 0 + hit_rate > 85% | 0.5x ttl | 内容新鲜度 |

**测试覆盖**：28 个测试覆盖 9 类规则 + 边界 + Web API + UI 渲染。

**CI**：#93 — 14/14 + CodeQL ALL_GREEN。

### V0.30.6 B6 — 章节导出 MD/TXT/EPUB（commit `4b70a11`）

**问题**：用户写完章节想导出到其他平台（GitBook / 番茄写作 / 邮件），但项目文件是 Markdown，其他格式需要手动转换。

**实现**：
- `src/novel2all/core/exporter.py`（387 行，**零外部依赖**——纯 stdlib + zipfile + xml.etree）
- `src/novel2all/web/app.py`：3 个新端点
- `tests/unit/test_exporter_v0306.py`：**35 个新测试**

**3 种格式**：

| 格式 | 实现 | 用途 |
|------|------|------|
| `.md` | `MarkdownExporter` | 直接透传 + 标准化 # 标题 |
| `.txt` | `TXTExporter` | 剥离 markdown 语法 + 规范化空行 |
| `.epub` | `EPUBExporter` | 完整 EPUB 3.0 |

**Web 端点**：

```bash
GET /api/chapter/1/export?format=md|txt|epub
GET /api/export?format=epub&title=我的书&author=我
```

**EPUB 3.0 结构**（手工构建）：

```
mimetype (无压缩)              # 必须 ZIP_STORED
META-INF/container.xml
OEBPS/content.opf              # metadata + manifest + spine
OEBPS/toc.ncx                  # EPUB 2 兼容导航
OEBPS/nav.xhtml                # EPUB 3 导航
OEBPS/chapter_NNN.xhtml        # 每章 XHTML（含 prev/next）
```

**3 个关键修复**：
1. HTTP header latin-1 only → filename 必须 ASCII-safe（用 `re.sub(r"[^\w\-]", "_", title)`）
2. EPUB 单章导出 = 完整 EPUB（不是裸 XHTML）——override `export_chapter()`
3. XML 转义所有 title/content（`& < > " '` → `&amp; &lt; &gt; &quot; &apos;`）

### 6.2 Prompt prefix cache 收益（V0.30.6 C1）

**100 章 novel 写作 workload，5 unique sys prompts：**

| 指标 | 数值 |
|------|-----:|
| Prefix hit rate | **95%** |
| Cost saved | **¥0.4655** |
| 总体节省比例 | **27.4%** |
| Input-only 节省 | **90%+** |

**计算口径**：
```
saving = hits × (miss_price - hit_price) × avg_input_tokens / 1M
       = 95 × (1.00 - 0.02) × 5000 / 1M
       = ¥0.4655
```

**业务影响**：
- ¥1.70（100 章 no cache） → ¥1.23（100 章 with prefix cache）= **¥0.47 / 100 章**
- 50 章小说节省 ≈ ¥0.23
- 100 章小说节省 ≈ ¥0.47
- 1000 章批量节省 ≈ ¥4.70
- **生产规模（10 万章）** ≈ ¥470

## 12. 反思

### 12.1 做对了什么

1. **解耦设计 > 合并实现**：PromptCacheTracker 独立 dataclass（V0.30.6 C1）+ CacheBase 抽象（V0.46）+ CacheBackend Protocol（V0.33）让每一层都可独立测试 + 替换。
2. **数据驱动决策**：V0.47-48 benchmark + V0.49 调优指南 + V0.51 推荐算法 + V0.30.6 C1 降本验证 = 9 个版本每个决策都有实测数据支撑。
3. **持续集成保护**：V0.52 cache-benchmark + Lint + Test + CodeQL = 4 层保护。advisory 模式让性能基准"温和"。
4. **Web UI 友好**：每个抽象都有 HTMX partial 实时面板（cache-panel / recommend / prompt cache / 进度条）——用户不需要读 docs 就能看懂系统在做什么。
5. **失败 → 修复 → 教训**：每次 lint fail / test fail 都立即修 + commit + 总结教训。V0.30.6 的 3 个 lint 修复 commit + 1 个 pre-existing fix commit 都是这种节奏。
6. **零外部依赖**：B6 章节导出（EPUB）用纯 stdlib + zipfile + xml.etree 实现 = 零新增依赖。
7. **¥ 视角 > token 视角**：V0.30.6 C1 用 ¥ 而不是 token 数显示节省，用户更直观。

### 12.2 做错了什么

1. **commit 前只 check 单文件**（2 次）：B6 和 C1 都因 ruff 全 src/ tests/ 检查失败。需要 commit 前必跑 `ruff check src/ tests/ scripts/` + `ruff format src/ tests/ scripts/`。
2. **V0.52 strict mode 误判**：第一版用本地 Windows baseline 在 CI ubuntu 跑 → 100% regression；第二版用 25% 阈值 → 仍 50% regression；第三版才上 advisory + 50% 阈值才稳定。**3 次迭代才稳定**——应该一开始就 advisory。
3. **测试名含"offpeak"但没 mock is_peak_hour**：5 个 pre-existing 测试 hidden 长达 1 周（CI 偶尔 fail 偶尔 pass），最终用 offpeak fixture 才解决。
4. **prompt_cache_tracker.py:45 comment 对齐**（CI #104 fail）：commit 前没 ruff format。
5. **V0.30.6 B3 第一次 git stash 灾难**：shim 环境删了 .git/refs/，本地未 commit 工作丢失 50%（_make_cache_key() 那段）。教训：**每次大改后立即 commit，git stash 是定时炸弹**。

### 12.3 关键启示

1. **数据驱动 > 直觉**：V0.51 推荐算法 / V0.52 CI 阈值 / V0.30.6 C1 降本估算 — 都基于 V0.47-48 benchmark 实测。
2. **advisory 模式 > strict blocking**：CI 性能基准必有抖动（±50%），continue-on-error 是行业标准。
3. **解耦 > 合并**：每层抽象独立（CacheBackend Protocol → CacheBase → 4 backend → PromptCacheTracker → cost_estimate）让测试 / 替换 / 升级都更容易。
4. **Web UI 是"文档的延伸"**：用户不需要读 docs，看实时面板就懂系统在做什么（B3 进度条 / V0.51 recommend / V0.30.6 C1 节省 ¥）。
5. **失败 → 修复 → commit → 总结**：每个失败都立刻 commit 修复 + 在 summary 里记教训。**不在 commit 里藏失败**。
6. **¥ 视角 > token 视角**：用户对钱敏感，对 token 数无感。
7. **零依赖 > 一切**：EPUB 用 stdlib，HTML 模板无 JS 框架，httpx 调 API — 减少依赖就是减少破坏面。

### 12.4 给团队的话

Cache 工程化（V0.33→V0.50）+ 智能推荐（V0.51）+ 性能守护（V0.52）+ Web UX（B3/B6）+ LLM 降本（C1）= **18 个 commit + 740 测试 + 689 行收官报告 + 13 个新文件 + 11 个修改文件 = 一套完整的"看得到 / 配得对 / 跑得快 / 写得顺 / 花得省"生产级缓存 + LLM 优化体系**。

下一阶段（C2 cost cap / C3 自适应路由 / B1 4-agent 审查 / B2 自动回滚）继续按这个节奏走：**数据驱动 → 抽象解耦 → Web UI 友好 → 持续集成保护 → 失败快速修复**。
