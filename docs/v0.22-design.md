# novel2all v0.22 — 设计蓝图

> **版本范围**：v0.22.0 → v0.22.2（3 个子版本）
> **目标**：解决"一致性"问题（L5 知识图谱 + 多模型路由）
> **完成时间预估**：~2 周
> **状态**：🚧 设计中（2026-09-12）

## 1. 背景

V0.21 解决了"漏掉历史"问题（5 层 memory 让 LLM 不再遗忘）。但仍有两个核心痛点：

1. **"角色关系在哪"**：林雷和苏寒是兄弟、师徒、仇敌？剧情复杂后纯文本 prompt 已不够用
2. **"伏笔因果链"**：A 伏笔 → B 事件 → C 揭示，纯靠 LLM 推演不可靠

**V0.22 主旋律**：构建 **L5 知识图谱**（结构化关系网）+ **多模型路由**（按任务选模型）。

## 3. L5 知识图谱

### 3.1 节点类型

| NodeType | 示例 | 必填字段 |
|---|---|---|
| `Character` | 林雷、苏寒 | name, alive |
| `Location` | 苍茫镇、青云宗 | name, type (city/sect/wild/...) |
| `Foreshadowing` | fs_bloodline_secret | id, status (active/advanced/revealed) |
| `Event` | ev_linlei_bloodline_awakening | in_world_time, location, characters |
| `Item` | 玉佩、黑剑 | name, owner |

### 3.2 边类型

| EdgeType | from → to | 含义 |
|---|---|---|
| `appears_in` | Character → Event | 角色出现在事件中 |
| `located_in` | Character → Location | 角色当前位置（动态） |
| `owns` | Character → Item | 角色拥有物品 |
| `related_to` | Character → Character | 关系（兄弟/师徒/仇敌/朋友） |
| `foreshadows` | Foreshadowing → Event | 伏笔预示事件 |
| `caused_by` | Event → Event | 因果链 |
| `set_in` | Event → Location | 事件发生地点 |

### 3.3 存储格式（嵌入 tracking state）

```json
{
  "graph": {
    "nodes": [
      {"id": "char:林雷", "type": "Character", "name": "林雷", "alive": true, "first_chapter": 1, "last_chapter": 50},
      {"id": "loc:苍茫镇", "type": "Location", "name": "苍茫镇", "type_detail": "city"},
      {"id": "fs:bloodline", "type": "Foreshadowing", "id_short": "fs_bloodline_secret", "status": "revealed"},
      ...
    ],
    "edges": [
      {"from": "char:林雷", "to": "event:awakening", "type": "appears_in", "chapter": 2},
      {"from": "char:林雷", "to": "loc:苍茫镇", "type": "located_in", "chapter": 1},
      {"from": "char:林雷", "to": "char:苏寒", "type": "related_to", "label": "兄弟"},
      ...
    ]
  }
}
```

### 3.4 API（`MemoryGraph` 类）

```python
class MemoryGraph:
    def add_node(self, node: GraphNode) -> None
    def add_edge(self, edge: GraphEdge) -> None
    def remove_node(self, node_id: str) -> None
    def get_node(self, node_id: str) -> GraphNode | None
    def get_neighbors(self, node_id: str, edge_type: EdgeType | None = None) -> list[GraphEdge]
    def get_path(self, from_id: str, to_id: str, max_hops: int = 3) -> list[GraphEdge] | None
    def query_subgraph(self, center: str, hops: int = 2) -> SubgraphResult
    def to_dict(self) -> dict
    def from_dict(self, data: dict) -> None
    def merge_chapter(self, chapter: int, nodes: list, edges: list) -> None  # 增量合并
    def nx_graph(self) -> nx.Graph  # 暴露 NetworkX 用于高级算法
```

### 3.5 集成点

1. **Extractor 增量**：每章末尾调用 LLM 提取节点/边（用 `instructor` 结构化输出）
2. **Manager.load_for_writing**：注入图谱上下文（角色关系、相关伏笔、相关事件）
3. **Verifier**：增加"关系矛盾"检查（已揭示的关系 vs 当前章节）
4. **Pipeline**：在 post-write check 后触发图谱 merge

## 4. Provider Router

### 4.1 任务类型

```python
class TaskType(str, Enum):
    WRITING = "writing"            # 长篇写作（最贵的活）
    CONSISTENCY = "consistency"    # 一致性检查（需要深度推理）
    EXTRACTION = "extraction"      # 结构化提取（便宜/快速）
    SUMMARIZATION = "summarization"  # 摘要压缩
    COVER = "cover"                # 封面/视觉
```

### 4.2 默认路由策略

| Task | 默认模型 | 回退 | 理由 |
|---|---|---|---|
| WRITING | deepseek-chat | - | 便宜 + 中文强 + 适合长输出 |
| CONSISTENCY | claude-sonnet-4 | deepseek-chat | 推理强 |
| EXTRACTION | gpt-4o-mini | deepseek-chat | 结构化输出便宜 |
| SUMMARIZATION | deepseek-chat | - | 便宜 |
| COVER | claude-sonnet-4 | gpt-4o | 视觉理解 |

> 用户可在 LLMConfig 覆盖任何任务的模型。

### 4.3 Router API

```python
class ModelRouter:
    def __init__(self, config: LLMConfig, task_routes: dict[TaskType, str] | None = None)
    def select(self, task: TaskType) -> str  # 返回模型名（litellm prefix）
    def call(self, task: TaskType, prompt: str, **kwargs) -> LLMResponse
    def call_with_fallback(self, task: TaskType, prompt: str, **kwargs) -> LLMResponse
    def cost_estimate(self, task: TaskType, prompt_tokens: int, completion_tokens: int) -> float
```

### 4.4 集成

- `LLMProvider.complete(task=TaskType.WRITING, ...)` —— router 接管模型选择
- pipeline 内部调用全部走 task_type
- 成本追踪：每次调用记录实际花费到 `tracking-state.json.cost_log`

## 7. 风险与回退

| 风险 | 缓解 |
|---|---|
| NetworkX 在某些 runner 不可用 | 加 fallback：纯 Python dict 实现基础图 |
| Extractor 提取噪声多 | 节点去重 + 置信度阈值 + 用户手动确认 |
| Router 选择不当导致成本爆炸 | 默认保守 + 成本日志 + 每日限额 |
| JSON 嵌入 tracking state 体积爆炸 | 增量 merge + 软删除（不真删，只标 active=false） |
