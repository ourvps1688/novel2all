# 09 · 本地手动验收清单

> 面向**不看代码的人**。每一步都说"应该看到什么"，不说"应该调用哪个接口"。
> 走这四个流程不需要理解任何技术概念；看到"不合格现象"栏里的任何一条，直接截图回报即可，不必自己判断是不是 bug。

---

## 0. 开始前

### 准备动作（按顺序）

| # | 动作 | 命令 | 这一步通过的样子 |
|---|---|---|---|
| 1 | 装依赖 | `pnpm install` | 无报错结束 |
| 2 | 起服务 | `pnpm dev` | 三个服务都起来；终端不再刷错误 |
| 3 | 服务端测试 | `pnpm test` | 全部通过 |
| 4 | 打开浏览器 | <http://localhost:5173> | 首页能渲染 |

第 3 步如果红了一两条，先别急着判产品有问题 —— 把报错贴出来给 team-lead，那是另一条线。

### 关于"全新用户"这个状态

流程一要求的不是新安装的浏览器，而是服务端的三个条件**同时成立**：

- 没有任何已配置且启用的文本模型
- 没有任何小说
- 没有任何自动导演任务

达到方式任选其一：用全新的库（`pnpm db:migrate` + 不执行 `pnpm db:seed`），或者在「设置 → 模型与供应商」里把已配置的模型全部移除。**推荐第二种**，改动小、随时能恢复。

### 一个贯穿全程的判断原则

**凡是"跳转到了某个页面"和"弹出了一个框"，性质完全不同。** 本轮改动的核心就是把前者改成后者 —— 如果流程一里你被跳去了某个 URL，而不是就地弹出配置框，那就是改动没生效。

## 1. 流程一 · 全新用户的首页引导（本轮改动最大）

**前置条件**：上节"全新用户"三条件成立。

### 操作步骤

1. 打开 <http://localhost:5173>
2. 看首屏，**先别点任何东西**，把看到的引导类区块数一遍
3. 点击它
4. 在弹出来的东西里完成一次模型配置（任意一个厂商 + 可用的 API Key + 模型名）
5. 观察流程走到"完成"之后发生了什么
6. 之后再来一次浏览器刷新 <http://localhost:5173>

### 预期结果

- [ ] 首屏出现配置提示，点击它 → **弹出配置对话框，URL 没有变**（地址栏仍然是 `http://localhost:5173`）
- [ ] 配完之后，对话框停留在原地，里面出现一个按钮，大意是"开始 / 去做第一本书"，**而不是自动跳转**
- [ ] 点那个按钮 → 落到"用一句话描述你想写的故事"的输入页
- [ ] 刷新首页 → 首屏那条提示**不再催促你配模型**，改成告诉你下一步该做什么（例如"用一句灵感开始"）
- [ ] 全程没有出现"页面不存在"、"找不到路由"一类的报错

### 不合格现象

| 现象 | 判定 | 说明 |
|---|---|---|
| 点了之后**跳到了另一个网址**，而不是弹出对话框 | **不合格** | 这正是本轮要修的死链，改动没生效 |
| 点开后出现的是一个**要你填书名、简介等字段的长表单** | **不合格** | 全新用户会被推去手动填表，而没模型时这条路产不出任何东西 |
| 弹窗配完之后**自动跳走**，来不及看清发生了什么 | 需确认 | 不一定是 bug，但请记下跳去了哪里 |
| 配完之后刷新首页，**旧提示还在原地**（还在催你配模型） | 轻微 | 数据最长会有约 15 秒延迟；等 15 秒再刷新仍有就是不合格 |
| 浏览器地址栏出现 `/help` | **不合格** | 这个页面本轮已删除，任何指向它的跳转都是漏网 |

### ⚠️ 这一条需要你的判断，不是 bug 与否

如果首屏同时出现了**两块都在催你配模型**的区域（一块带黄色警示底色，一块是普通卡片），且两块的按钮文案还不一样（例如一块写"快捷配置"、另一块写别的词）—— **不要当成故障，请直接截图回报。**

这是我在检查时发现的现象：`Home.tsx:226` 和 `:227` 连续渲染了两个都指向"配模型"的区块，它们的按钮文案不同但做的是同一件事。对一个全新用户来说，同一件事出现两种叫法，是比"难看"更严重的完成安装障碍。**这条要不要改，由 team-lead 定，不进本次验收的通过/不通过口径。**

## 2. 流程二 · 设置总览页

**前置条件**：已完成流程一（有可用模型）。

### 操作步骤

1. 进入「设置」
2. 看页面上方那张状态卡
3. 看下面那排卡片，数一下有几张
4. 逐张看卡片底部的那行灰色小字
5. 再进来一次「设置 → 自动导演」，把"自动通过"相关的选项全关掉，回总览页看那张卡的灰字
6. 再把其中任意 1 到 2 项打开，回总览页再看

### 预期结果

- [ ] 总览页是 **3 张卡**：模型与供应商 / 自动导演 / 知识库与写法
- [ ] 「模型与供应商」底部显示你接的是哪家厂商和模型名；如果已经指定了创作步骤，会一并说"已指定 N 个创作步骤"
- [ ] 「自动导演」在全关时显示：**每个关键环节都会等你确认**
- [ ] 打开 1 到 2 项后，同一张卡的说法变成"有若干环节 AI 会直接走下去、其余等你确认"
- [ ] 「知识库与写法」在没有开启资料检索时，显示它是**可选的**、不影响开始创作

### 不合格现象

| 现象 | 判定 | 说明 |
|---|---|---|
| 还能看到第 4 张卡（大意是"数据与备份 / 桌面与维护"之类） | **不合格** | 本轮已删，且 Phase 1 的历史叫法不应再有残留 |
| 「模型与供应商」在你明明配好了的情况下仍然说"还没接上模型" | **不合格** | 卡片没读到真实状态，退回成写死的文案了 |
| 「自动导演」灰字出现一串**看不懂的过程名**（类似"卷战略""节奏拆章""XX 通过后继续"这样连成一长句） | **不合格（文案）** | 见下方说明 |
| 三张卡的灰字全都一模一样 | **不合格** | 说明它们没读各自的状态 |

### 关于第 3 条不合格

总览页那套"哪些环节不用等你确认"的说法，在**全关**和**只开 1 到 2 项**时是说得通的；但一旦开了多项，它会把内部过程名原样拼成一长句（实际文案形如「候选方向确认后继续、角色准备通过后继续 等 5 项 会自动通过」）。

**这不是显示 bug，是文案层的问题**，对新手来说读不懂。我的建议是这个位置只说数量、不列明细 —— 明细应该留给「设置 → 自动导演」里面的选项本身去解释。**请记录：你在这一步实际看到了几个项目名。** 这条同样由 team-lead 决定是否在本轮改。

## 3. 流程三 · 自动导演跑一轮（回归基线）

**这条流程本轮一行没改。** 它存在的意义是：如果前两条的手感不对，用这条确认是"产品改动导致"还是"本来就这样"。

**前置条件**：有可用模型；有网络（这一步会真实调用大模型，会产生费用）。

### 操作步骤

1. 打开「写小说」的 AI 入口（首页那句"自动导演写长篇"对应的入口）
2. 输入**一句话**灵感，越短越好（例如"一个失忆的邮差在末世里替人送信"）
3. 提交，然后**不要关页面**，原地观察
4. 中途会出现需要你做选择的地方，按提示选一个，继续观察
5. 一直走到出现可读的第一章内容为止

### 预期结果（跑到哪一步算通过）

按顺序都应该发生，前四步是**必须**：

- [ ] **出现 2 个候选方向让你挑**（这时可以要求你看的是"哪个更想读下去"，而不是要你填任何专业设定）
- [ ] 挑完后自动往下走，中途**不需要你逐项审核**（会有一串准备工作在后台完成）
- [ ] 之后出现一次**生产方式的选择**（大意是：AI 一路写完整本书 vs 进入可编辑的完整工作台）—— 选"简易创作"那条更容易走到终点
- [ ] 最终出现**可以阅读的第一章**，或者一个明确告诉你"正在写第一章 / 还要多久"的进度区
- [ ] 全程没有被要求填写世界观字段、角色字段或分卷字段

### 不合格现象

| 现象 | 判定 | 说明 |
|---|---|---|
| **没有出现 2 选 1 的方向选择**，直接就开始写正文 | **不合格** | 主链丢了第一个检查点 |
| 走到一半**永久停住不动**，既没有报错也没有下一步 | **不合格** | 请记下停在哪个标题上 |
| 出现了需要"处理 / 修一下"之类的提示，但点了之后**又回到同一个提示** | **不合格** | 请截图，这条最有价值 |
| 页面出现技术词（例如包含"暂停""失败重试""恢复""接手""排队"这类内部说法） | **不合格** | 本轮的目标就是把这套词从用户视野清掉 |
| 走到终点耗时长得离谱但没有进度提示 | 需确认 | 不一定是故障，属体验问题，记下来即可 |

### 重要边界

走到"第一章可读"就算通过。**不必等整本书写完**，也不必验证后面几十章。这条流程的作用是确认主链没断。

## 4. 流程四 · 世界样本库与工作台

**这条最容易误判，请先看这一段：**

> **世界样本库不需要你手动"存入"。**
> 你在自己的小说里搭好一场世界观，系统会在同一步操作里自动把它收进样本库。**不要因为库里一开始是空的就以为它坏了。**

**前置条件**：流程三里已经用 AI 生成了一本书（至少走到"第一章可读"）。

### 操作步骤

1. 打开「世界 / 世界样本库」列表页
2. **先看是不是空的** —— 如果流程三已经跑完，这里**应该已经有内容**了
3. 点进其中一条，确认能打开详情/工作台
4. 在工作台里做一次小改动并保存
5. 回到列表页看那条有没有更新
6. （可选验证"不用手动存"）另外开一本新小说，在小说设定区里新建一个世界，保存后回到列表页

### 预期结果

- [ ] 流程三跑完之后，列表页**不是空的**，里面至少有流程三那本书沉淀下来的世界
- [ ] 列表页每条目能看到名称、类型和一段摘要
- [ ] 点进去能打开这个世界的工作台，里面的内容能读
- [ ] 在工作台里做的修改能保存，且不报错
- [ ] 回到列表页，那条还在这里
- [ ] 第 6 步做完之后，列表页**多出一条**，全程没有点过任何"存入样本库"之类的按钮

### 不合格现象

| 现象 | 判定 | 说明 |
|---|---|---|
| 列表页是空的，且第 6 步做完之后**仍然是空的** | **不合格** | 说明"小说里的世界自动入库"这一环断了，这条很关键 |
| 列表页**找不到任何"新建世界"的按钮**，同时页面也没告诉你东西从哪来 | **不合格** | 生成器本轮删了，但页面必须解释清楚"世界是随你的小说沉淀下来的" |
| 打开工作台后内容是空的，或者一直转圈 | **不合格** | 请截图，可能是保留下来的工作台读不到数据 |
| 在工作台里保存失败 | **不合格** | 请记下错误提示原文 |
| 还能找到"生成第一个世界样本"这类按钮 | **不合格** | 那是被删掉的向导留下的，点了会去不存在的页面 |

### 关于"列表空着"的一个判断

如果你的库确实为空（比如刚重置了数据库），看到的是一段**解释性**的空状态：告诉你还没有可复用的世界，并说明它会在你写小说的过程中自动出现，同时给一个去"我的小说"的入口。**这是一个合规的空状态，不是 bug。**

和它的区别只在：坏的空状态会让你以为"这个功能没法用"，好的空状态会告诉你"怎么用筷子"。本轮改的就是这个文案 —— 顺手也请你判一下：那段话你是不是看懂了。

## 5. 跨流程：一旦出现这些，直接停下回报

| 现象 | 为什么重要 |
|---|---|
| 出现英文报错串、或者写着"undefined / null / Not Found"的提示 | 这是给用户看的界面出现了内部口号，任何位置都是缺陷 |
| 任何位置出现"已下线""已迁移""原 X 现改为 Y""之前可以在这"这类说法 | UI 文案规则明令禁止：不许向用户叙述产品自己的变化 |
| 同一个功能在两处叫两个名字 | 新手会以为是两个东西 |
| 界面上出现"恢复""接管""排队""接手"这类词 | 本轮技术词清理的漏网 |
| 移动端窗口下，某个按钮只剩图标没有文字 | 触屏上无法辨认 |
| 点击后有反应但是看不见任何提示（静默失败） | 最糟糕的一类：用户以为自己点错了 |
