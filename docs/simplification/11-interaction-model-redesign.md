## 一、五条交互设计原则

1. **单一主流程**：灵感 → 方向 →〔AI〕→ 正文 → 整本是一条线。任何"高级模式/专家分支"默认藏起，不摆在起点。
2. **状态唯一且常驻**：一本书只有一个"现在在哪 / 为什么停 / 下一步"面板；禁止恢复横幅在多处重复出现。
3. **恢复零寻找**：任何阻塞 / 待确认，动作入口就长在状态面板里；不允许用户自己找位置点。
4. **默认值代替选择**：能默认的不问；必须问的只问一次、且用一句话。
5. **AI 先做完，用户再确认**：AI 跑完一个可交付单元再交回，不在中途反复要用户决策。

## 二、目标交互蓝图：一句话到整本书

```
一句话灵感
   └─▶ 〔AI 全自动〕生成 2 套方向
          └─▶ ★ 用户选 1 套            （强制选择，唯一）
                 └─▶ 〔AI 全自动〕世界 / 角色 / 卷战略 / 章节任务
                        └─▶ ★ 用户选生产方式       （一次选择，可暂搁）
                               simple → 〔AI〕全自动写完整本
                               studio → 进入专业工作台（专家路径，默认不显）
                        └─▶ 〔AI 全自动〕正文 + 审校 + 修复
                               └─▶ ★ 用户读成稿
```

**用户全程动作只有 3 个**：选方向、选生产方式、最后读。其余交给 AI。
**新手默认路径就是 simple 那条直线**；studio 是专家出口，不在起点出现。

## 四、砍 / 合并 / 下沉

- **砍**：起点处的模式选择（P4）；`/assets` 一级页（P2）；把阶段术语（`候选阶段 / 结构大纲 / 章节执行 / 管线 / 质量修复`）当导航给用户看。
- **合并**：多个分散界面 → 一个"本书工作区"主视图 + 一个极简抽屉（仅需要时展开）。候选/大纲/执行/质量修复都在这一个视图里以步骤呈现，不再各自开页。
- **下沉**：世界 / 角色 / 卷等编辑能力，在工作区内有入口即可，不进首页或一级导航平铺（呼应 C11：世界样本库靠小说沉淀，不靠独立入口）。
- **收敛模式**：5 → 1（智能自动）。

## 六、最该优先砍掉的复杂度

**首推砍：把运行模式与阶段概念直接暴露给新手（5 种模式 + 多阶段多界面）。** 它制造了约 80% 的认知负荷 —— 新手还没写一句话就被要求理解"我选哪种模式、我在哪个阶段"，而它们对完成第一本书毫无帮助。

**但若问"先做什么能最快、最低风险地降复杂度"：是 P0 合并恢复横幅。** 它纯聚合、不动主链、且已有恢复定位工作打底，半天能见效。换句话说：**最该砍的是模式暴露，最先动手的是横幅合并** —— 两者不矛盾，一个定方向、一个抢早期胜利。
