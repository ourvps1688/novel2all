## 1. 目标

V0.24 prompt cache 留下 **4 个核心问题**：

| # | 问题 | 影响 | 解决版本 |
|---|------|------|----------|
| 1 | **伪 LRU**（超 max_size 清空全部） | 命中率永远 0%，功能失效 | V0.29 真 LRU（前置） |
| 2 | **无 TTL**（LLM 升级后旧回答仍命中） | 返回 stale 数据，幻觉风险 | V0.33 |
| 3 | **无持久化**（重启后命中率归零） | 启动慢 + LLM 成本高 | V0.33 JSON / V0.40 SQLite |
| 4 | **无跨进程/跨 OS 安全**（多进程 race + 跨 OS 不互斥） | 数据损坏 + 多进程不安全 | V0.37 文件锁 / V0.40 SQLite 内置锁 |

**V0.33-V0.49 主旋律**：用 17 个版本把 cache 从「单进程内存玩具」升级为「**生产级分布式缓存体系**」——多 backend × 跨 OS 安全 × 工程化加固 × 完整基准 × 部署指南。

**关键设计原则**：
- **后端抽象**（V0.33）：`CacheBackend` Protocol 让 memory / json / sqlite / redis 互通
- **降级策略**（V0.37 / V0.46）：缺失能力时 warning + 安全降级（如无锁 → 无锁运行）
- **OS-agnostic**（V0.40 / V0.46）：用 SQLite 内置锁 + Template Method 模式替代手写 OS 适配
- **数据驱动**（V0.47-48）：每个架构决策都有 benchmark 实测数据支撑
- **可演进**（V0.46）：CacheBase 抽象让未来加新 backend 只需 5 行代码

### 3.2 V0.37 跨进程文件锁 — `ca1...`

**问题**：多进程并发写 JSONFileBackend 时 race condition（最后一个写入胜出，丢失数据）。

**修复**（`core/cache.py` + `CacheLock`）：
```python
class CacheLock:
    """V0.37：跨平台文件锁（POSIX fcntl / Windows msvcrt）。"""
    def __init__(self, target_path):
        if sys.platform == "win32":
            try:
                import msvcrt  # 探测
                self._backend = "msvcrt"
            except ImportError:
                pass
        else:
            try:
                import fcntl
                self._backend = "fcntl"
            except ImportError:
                pass
        if self._backend == "none":
            logger.warning("降级为无锁模式（多进程不安全）")

    def __enter__(self):
        if self._backend == "msvcrt":
            self._fd = os.fdopen(os.open(
                str(self.lock_path),
                os.O_CREAT | os.O_RDWR | os.O_BINARY,  # 关键：避免 "w" truncate
                0o644), "rb+")
            # ... ensure 1 byte + msvcrt.locking ...
        else:
            self._fd = open(self.lock_path, "w")
            fcntl.flock(self._fd.fileno(), fcntl.LOCK_EX | fcntl.LOCK_NB)
```

**关键能力**：
- 跨平台锁（fcntl on POSIX / msvcrt on Windows）
- 降级模式（无锁时 warning + 无锁运行）
- 注意：**POSIX 锁 vs Windows 锁不互通**（跨 OS 共享仍不安全）

**2.2 自动 backup**：
```python
def _check_and_recover(self) -> None:
    # Step 1: magic 头快速检查（避免 integrity_check 锁文件）
    with open(self._path, "rb") as f:
        header = f.read(16)
    if not header.startswith(b"SQLite format 3"):
        self._rename_corrupt()  # ← V0.42 关键：magic 先查
        return
    # Step 2: integrity_check 深度检查
    test_conn = None
    try:
        test_conn = sqlite3.connect(str(self._path), timeout=5.0)
        if test_conn.execute("PRAGMA integrity_check").fetchone()[0] != "ok":
            self._rename_corrupt()
    finally:
        if test_conn is not None:
            test_conn.close()  # ← V0.42 关键：try/finally

def _rename_corrupt(self) -> None:
    # 清理 -wal/-shm/-journal 残留（Windows rename 必需）
    for suffix in ("-wal", "-shm", "-journal"):
        extra = self._path.with_suffix(self._path.suffix + suffix)
        if extra.exists():
            extra.unlink()
    self._path.rename(self._path.with_suffix(f".corrupt.{ts}.db"))
```

def migrate_cache(src_backend, dst_backend, src_path, dst_path,
                  max_size=1024, ttl_seconds=0, ...):
    src = _open_backend(src_backend, src_path, max_size=8192)
    dst = _open_backend(dst_backend, dst_path, max_size, ttl_seconds)

### 3.7 V0.46 CacheBase 抽象基类 — `39f42c9`

**问题**：4 backend（MemoryLRU / JSONFile / SQLite / Redis）有 ~85 行重复样板（__init__ 公共字段 + stats() 10 行字典 + close() no-op + clear() 重置）。

**修复**（`core/cache.py` 新增 CacheBase）：
```python
class CacheBase(ABC):
    """V0.46：Template Method 模式 + 钩子方法。"""
    backend_name: ClassVar[str] = "unknown"

    def __init__(self, *, max_size=256, ttl_seconds=0):
        self._max_size = max_size
        self._ttl_seconds = ttl_seconds
        self._hits = 0
        self._misses = 0

    def _stats_persist_path(self) -> str | None:
        return None  # 子类覆盖

    def _stats_lock_backend(self) -> str:
        return "none"  # 子类覆盖

    def _stats_extras(self) -> dict[str, Any]:
        return {}  # 子类覆盖

    def stats(self) -> dict[str, Any]:
        total = self._hits + self._misses
        hit_rate = self._hits / total if total > 0 else 0.0
        return {
            "enabled": True, "backend": self.backend_name,
            "size": self.size(), "max_size": self._max_size,
            "hits": self._hits, "misses": self._misses,
            "hit_rate": round(hit_rate, 4),
            "ttl_seconds": self._ttl_seconds,
            "persist_path": self._stats_persist_path(),
            "lock_backend": self._stats_lock_backend(),
            **self._stats_extras(),
        }

    def _reset_stats(self) -> None:
        self._hits = 0
        self._misses = 0

    def close(self) -> None: ...  # 默认 no-op
```

**4 backend 全部继承**：
```python
class MemoryLRUBackend(CacheBase):
    backend_name = "memory"
    # 仅实现 get/set/size/clear/keys，无 stats/close 重复

class JSONFileBackend(CacheBase):
    backend_name = "json"
    def _stats_persist_path(self) -> str | None: return str(self._path)
    def _stats_lock_backend(self) -> str: return self._lock_backend

class SQLiteBackend(CacheBase):
    backend_name = "sqlite"
    def _stats_persist_path(self) -> str | None: return str(self._path)
    def _stats_lock_backend(self) -> str: return "sqlite"
    def _stats_extras(self) -> dict: return {"conn_pool_size": len(self._conns)}

class RedisBackend(CacheBase):
    backend_name = "redis"
    def _stats_persist_path(self) -> str | None: return self._url
    def _stats_lock_backend(self) -> str: return "redis"
    def _stats_extras(self) -> dict:
        return {"namespace": self._namespace, "used_memory_bytes": ...}
```

**收益**：
- 消除 ~85 行重复样板
- 单一来源（未来加新 backend 5 行代码即可）
- 类型一致（4 backend 共享统一 stats 字典结构）
- 向后兼容（CacheBackend Protocol 不变，stats() 字段顺序与 V0.45 一致）

## 7. 部署指南要点（V0.49 cache-tuning-guide.md）

### 7.1 Backend 选择决策树

```
部署形态？
├─ 单进程 → memory (开发) / sqlite (持久化)
├─ 多进程本地 → sqlite (WAL 读并发) / redis (≥5 进程)
├─ 多机器同 region → redis (loopback)
└─ 多 region → ❌ Redis 直连 / ✅ Redis + region-local SQLite
```

### 7.2 TTL 推荐

| 内容类型 | TTL | 理由 |
|----------|----:|------|
| 角色卡 / 世界观 | 0（永不过期） | 频繁复用 + 几乎不变 |
| 章节细纲 | 86400（24h） | 短期复用 |
| 完整章节 | 604800（7天） | 重写概率低 |
| LLM 调试 | 3600（1h） | prompt 频繁调整 |

### 7.3 max_size 推荐

| 场景 | max_size | 内存上限（800 char values） |
|------|---------:|---------------------------:|
| CLI / 一次性 | 256 | 200 KB |
| 开发 / 调试 | 512 | 400 KB |
| 单用户 web | 1024 | 800 KB |
| 多用户 web | 4096 | 3 MB |
| 大规模爬虫 | 16384 | 13 MB |

### 7.4 监控告警

- `cache_hit_rate < 0.5` → 收益低，考虑关闭
- `cache_misses / cache_hits > 1` → miss 突增
- `redis_used_memory / redis_max_memory > 0.9` → 即将驱逐

## 12. 反思

### 12.1 做对了什么

1. **抽象先行**（V0.33 CacheBackend Protocol）— 让 V0.40/V0.45/V0.46 新 backend 零侵入接入
2. **数据驱动**（V0.47-48 benchmark）— 消除架构决策的猜测，让"为什么选 sqlite"有数据支撑
3. **失败透明**（V0.42 自动 backup）— 不掩盖损坏 DB，而是自动备份 + 重建
4. **工程化加固**（V0.42-43）— thread-local pool / integrity check / 平滑迁移 / 显式 close
5. **可演进性**（V0.46 CacheBase）— 加新 backend 只需 5 行，未来 DynamoDB/Memcached 接入零成本

### 12.2 做错了什么 / 学到的教训

1. **V0.33 没直接用 SQLite**：选 JSON 是因为"零新依赖 + 易调试"，但 V0.40 又切回 SQLite（白绕一圈）。**教训**：如果性能关键 + 有标准库支持，应优先选成熟方案（SQLite）。
2. **V0.37 跨平台锁限制未明示**：POSIX 锁 vs Windows 锁不互通，但 V0.37 没在文档明确标"⚠️ 跨 OS 共享不安全"。**教训**：架构限制必须在显眼位置标注，避免用户踩坑。
3. **V0.40 → V0.42 重构代价大**：单连接 → thread-local pool 是大改，且涉及 LLMProvider.close()。**教训**：早期就用 thread-local（参考 Java ThreadLocal），避免后期重构。
4. **V0.46 才抽 CacheBase**：V0.33 → V0.45 重复样板拖了 13 个版本。**教训**：第 3 个 backend 出现时就该抽基类（rule of three）。
5. **V0.47-48 没真 Redis 测试**：环境无 Docker，benchmark 数据有 1-2 个数量级不确定性。**教训**：CI 应集成 Redis service container，避免基准数据依赖 fakeredis。

### 12.3 关键启示

- **抽象 vs 具体的平衡**：太早抽象（V0.33 1 个 backend 就抽）浪费；太晚抽象（V0.46 4 个 backend 才抽）成本大。**Sweet spot 是第 3 个 backend 出现时**。
- **降级 vs 严格的平衡**：V0.37 锁不可用时 warning + 无锁运行（降级），V0.40 SQLite 内置锁（严格）。**降级用于"缺失能力"，严格用于"能力存在但需启用"**。
- **测试覆盖 vs 测试成本的平衡**：V0.45 fakeredis 让 CI 无需 Redis 服务；V0.46 CacheBase 测试覆盖 4 backend 共 39 tests。**Mock + 真实组合测试是甜蜜点**。
- **数据 vs 直觉**：V0.47 benchmark 数据（sqlite 比 json 快 45x）推翻"JSON 兼容性更好所以生产应该用 JSON"的直觉。**直觉需要数据验证**。

### 12.4 致团队

V0.33 → V0.49 用了 17 个 commit 把 cache 从"单进程内存玩具"升级为"生产级分布式缓存体系"。下一步重点：

1. **监控和可观测性**（V0.51-52）：让用户能实时看到 cache 健康度
2. **性能持续集成**（V0.52）：每次 PR 跑 benchmark，防回归
3. **多 region 实战**（V0.53+）：跨城部署验证 region-local cache 模式

文档化和测试化是这次成功的关键——每个版本都有 docs + tests + 实战数据支撑，避免"代码即文档"的反模式。
