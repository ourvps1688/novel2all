### 关键技术决策（保留供参考）
1. **classic PAT + `repo` scope**：fine-grained PAT 即便 owner 也拿不到 logs API（403）
2. **跟随重定向不要带 Authorization**：S3 用 query-string 签名，带 Bearer 会 401
3. **chromadb 三平台差异**：沙箱 Windows DLL 缺失、Linux/macOS onnxruntime 偶发、Windows runner 句柄不释放
4. **ruff format + ruff check 双跑**：CI 跑两个，本地必须两个都跑
5. **mock `_extract_chapter` 必须从 content 段提取**：不能从 previous_state 的 last_chapter
6. **fail-soft 设计原则**：force_mode 是"首选"而非"必须"，失败时优雅降级

## Step 2 设计 —— 完整 skill pipeline + LLM 真写

### 目标
让 CLI `novel2all write chapter 5` 真正调 LLM 生成一篇 ≥2000 字小说章节，并自动:
- 加载 memory context（用 Step 1 的 retriever + summarizer）
- 调用对应 skill（story-long-write）的 prompt 模板
- 流式输出到 console
- 写完后自动调 Extractor + Verifier + retriever 入库

### 工作量
- 核心 pipeline：`core/pipeline.py`（约 300 行）
- skill 注册机制完善（13 个 skill 都注册到 pipeline）
- CLI `write chapter` 接入真实 LLM
- 流式输出处理
- 测试：mock LLM 验证 pipeline 流程，真实 LLM 跑 1 章
- **估算**：5-6 天

### 接口设计

#### `core/pipeline.py`
```python
class WritingPipeline:
    """写作 pipeline，统一编排：memory load → skill prompt → LLM → save."""

    def __init__(
        self,
        manager: MemoryManager,
        skill_registry: SkillRegistry,
        role_registry: RoleRegistry,
        llm: LLMProvider,
    ):
        self.manager = manager
        self.skill_registry = skill_registry
        self.role_registry = role_registry
        self.llm = llm

    async def write_chapter(
        self,
        *,
        chapter: int,
        outline_path: Path,
        characters_involved: list[str],
        skill_name: str = "story-long-write",
        stream_callback: Callable[[str], None] | None = None,
    ) -> tuple[Path, TrackingState, list[ConsistencyIssue]]:
        """写第 N 章，完整流程。

        Returns:
            (output_path, updated_state, post_write_issues)
        """
        # 1. pre-write check
        issues = await self.manager.pre_write_check(chapter, outline_text)
        if Verifier.has_blocking_issues(issues):
            raise BlockingIssuesError(issues)

        # 2. 加载 memory context
        ctx = await self.manager.load_for_writing(
            chapter=chapter,
            chapter_outline=outline_text,
            characters_involved=characters_involved,
        )

        # 3. 选 skill 并组装 prompt
        skill = self.skill_registry.get(skill_name)
        prompt = skill.render_prompt(
            outline=outline_text,
            memory_context=ctx,
            characters=characters_involved,
        )

        # 4. 流式 / 整体调 LLM
        content = ""
        async for chunk in self.llm.stream(prompt=prompt, system=skill.system_prompt):
            content += chunk
            if stream_callback:
                stream_callback(chunk)

        # 5. 写文件
        output_path = self.project_root / "正文" / f"第{chapter:03d}章.md"
        output_path.write_text(content, encoding="utf-8")

        # 6. update memory + post-write check
        state, post_issues = await self.manager.update_after_writing(chapter, content)

        return output_path, state, post_issues
```

#### CLI `write chapter` 升级
```python
@app.command()
def write_chapter(
    chapter: int = typer.Argument(...),
    outline_file: Path = typer.Option(None, "--outline", "-o"),
    skill: str = typer.Option("story-long-write", "--skill", "-s"),
    stream: bool = typer.Option(True, "--stream/--no-stream"),
) -> None:
    """写第 N 章（真实 LLM 调用）。"""
    manager, pipeline = _build_pipeline()
    project = ProjectStructure(root=get_project_root())

    def on_chunk(chunk: str) -> None:
        if stream:
            typer.echo(chunk, nl=False)

    output_path, state, issues = asyncio.run(
        pipeline.write_chapter(
            chapter=chapter,
            outline_path=outline_file or project.chapter_outline(chapter),
            characters_involved=list(state.characters.keys())[:3],
            skill_name=skill,
            stream_callback=on_chunk,
        )
    )

    console.print(f"\n[green]✓[/green] 第 {chapter} 章已生成：{output_path}")
    if issues:
        console.print(f"[yellow]⚠ {len(issues)} 个一致性问题[/yellow]")
```

### Skill Prompt 模板要求
- 必须从 13 个 skill markdown 里读 frontmatter + body
- skill 必须有 `user_invocable: true` 才允许作为 `--skill` 参数
- story-long-write 的 prompt 应包含：
  - memory context（4 层 core/character/recent/events）
  - 细纲
  - 涉及角色列表
  - 文风锚点（从 memory.config.style_anchor 读）

### 错误处理
- `BlockingIssuesError`：pre-write check 有 critical → 中止
- `LLMError`：LLM 调用失败 → 重试 3 次（用 tenacity）
- `OutlineNotFound`：没找细纲 → 中止并提示用户写

#### 后端 `web/app.py`
```python
@app.post("/api/write/stream")
async def write_chapter_stream(req: WriteChapterRequest):
    """流式返回 LLM 生成进度（SSE）。

    SSE event types:
      - "chunk": {"content": "..."} (LLM 输出的部分)
      - "progress": {"step": "memory_load"|"llm"|"extract", "pct": 0.5}
      - "done": {"output_path": "...", "issues": [...]}
      - "error": {"message": "..."}
    """
    async def event_generator():
        manager, pipeline = _build_pipeline()

        async def on_chunk(chunk: str):
            yield f"event: chunk\ndata: {json.dumps({'content': chunk})}\n\n"

        # 调用 pipeline，stream_callback 改为 SSE yield
        # ...

    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

## 优先级建议

如果只有一次"完整会话"时间，建议顺序：

1. **Step 2 核心 pipeline（2-3 天）**：写 `core/pipeline.py` + mock 测试，CLI 升级
2. **Step 2 真 LLM 验证（1 天）**：用 DEEPSEEK 或 ANTHROPIC 跑 1 章，确认端到端可用
3. **Step 3 Web SSE（2-3 天）**：前端 + 后端
4. **Step 3 50 章真实跑（1-2 天）**：替换 mock，验证 token/时间/质量

总预算 6-9 天。

## 已知风险与缓解

| 风险 | 缓解 |
|---|---|
| LLM 输出字数不足 2000 | prompt 显式要求"请写至少 2000 字"，post-check 失败重试 |
| LLM 偏离文风（style_anchor） | Verifier post-write 检查文风，warning 提示 |
| LLM API 不稳定 | tenacity retry 3 次 + 指数退避 |
| 端到端 50 章 token 消耗过大 | 每章预算 ≤ 8000 tokens，总 50 章 ≤ 400K tokens（按 DeepSeek 价格约 $5-10） |
| 真实 LLM 与 mock 行为不一致 | Step 1 已验证 mock 等价于真 LLM 提取结果（因为 mock 模拟的是"作者"提取逻辑，不是 LLM 推理） |
